# プライバシーポリシー

_最終更新: %YEAR%_

DishyWarden は Starlink 端末向けのデスクトップ監視ツールです。
**テレメトリは原則すべてあなたの端末内に留まる**ように設計されています。
この文書では、端末の外に送信される可能性があるのは 2 つの場面だけであることと、
それぞれを無効にする方法を説明します。

---

## 1. 端末外へ出ないデータ

以下は**ローカルにのみ保存**され、送信されません:

| データ | 保存場所 |
|---|---|
| テレメトリサンプル（電波、レイテンシ、スループット、稼働率） | ユーザーデータディレクトリの `telemetry.db`（SQLite） |
| アラートとそのライフサイクル | ユーザーデータディレクトリの `alerts.db`（SQLite） |
| 設定、プローブノード、通知設定 | ユーザーデータディレクトリの通常の JSON ファイル |
| 通知の資格情報（Telegram ボットトークン、webhook URL、メールのパスワード） | 同じローカルの JSON ファイル |

サーバーがアカウント、通知の資格情報、ファイルパス、ホスト名を受け取ることは
**ありません**。

## 2. 外向きの通信は 2 つ

### 2.1 アップデートの確認 — 自動、最小限

新しいバージョンを知らせるため、アプリは `cloud.dishywarden.com` の
更新マニフェストにアクセスして結果を報告します。

**送信されるもの:** 匿名の `client_id`（端末上で生成したランダム UUID v4）、
アプリのバージョン、プラットフォーム、そしてリクエスト元の IP アドレス。

**送信されないもの:** 第 1 節に挙げた項目すべて。

**保持期間:** 更新イベントは 90 日で削除されます。アクセスログは 14 日でローテーション。

**無効にする方法:** *設定 → アップデートとフィードバック* で更新フィード URL を
空にするか、クラウドのエンドポイントを消去してください。以後、アプリはクラウドに
まったく接続しません。

### 2.2 誤検知の報告 — 既定では無効、同意が必要

アラートを誤検知としてマークした場合、アプリはアラートルールを調整するために
匿名の報告を送信できます。**この機能は既定では無効です。**

**送信されるもの:** アラートの種別、重要度、タイトル、任意のメモ、
アプリのバージョン、プラットフォーム、匿名の `client_id`、IP アドレス、
および —— 設定に位置情報が残っている場合のみ —— あなたの座標。

**送信されないもの:** アカウント、通知の資格情報、ファイルパス、ホスト名、
およびその他のテレメトリ。

**保持期間:** フィードバックは 90 日で削除されます。

**無効にする方法:** *設定 → アップデートとフィードバック → 誤検知のサンプルを
報告する* を無効のままにしてください。最初の送信時には、送信される項目を
明示したうえで明示的な確認を求めます。クラウドのエンドポイントを消去すれば、
外向きの通信をすべて止めることもできます。

## 3. 匿名の方法

- `client_id` は端末上で生成されたランダムな UUID v4 です。
  ハードウェア識別子、アカウント、ネットワーク識別子からは**導出されません**。
  サーバーがこれを使ってあなた個人を関連付けることはできません。
- フィールドのホワイトリストは**クライアント側とサーバー側の双方で**強制されます。
  リストにないフィールドは、送信されなくても破棄されます。
- クラウドのエンドポイントは IP アドレスごとにレート制限されます。

## 4. データの取り扱い場所

クラウドサービスは、日本に配置されたプロジェクトメンテナーが運用する
単一サーバー上で動作します。上記のデータを、UTC の日付ごとに
追記書き込みの JSON ファイルとして保存します。

## 5. Do Not Track / Cookie

DishyWarden はデスクトップアプリケーションです。Cookie を設定せず、
トラッカーを動かさず、アナリティクスを組み込まず、
サードパーティのサービスがデータを受け取ることもありません。

## 6. あなたの権利

データは匿名であるか自発的に提供されたものであり、短いスケジュールで削除されるため、
以下の方法で権利を行使できます:

- 第 2 節の通信を無効にする
- 設定でクラウドのエンドポイントを消去する
- メンテナーに特定の `client_id` のデータを削除することを依頼する

削除のご依頼は、リポジトリに issue を作成するか、メンテナーに直接ご連絡ください。

## 7. 本ポリシーの変更

重要な変更は、それを導入するバージョンのリリースノートでお知らせし、
上記の「最終更新」日付を変更します。

## 8. 連絡先

プライバシーに関する質問はリポジトリの issue か、メンテナーへの直接連絡で
受け付けています。
