# 개인정보 처리방침

_최종 수정: %YEAR%_

DishyWarden는 Starlink 단말을 위한 데스크톱 모니터링 도구입니다.
**원격 측정 데이터는 기본적으로 사용자의 컴퓨터 안에 남도록** 설계되어 있습니다.
이 문서는 단말 밖으로 나가는 두 가지 경우와 각각을 끄는 방법을 설명합니다.

---

## 1. 절대 컴퓨터 밖으로 나가지 않는 데이터

아래 데이터는 **로컬에만 저장**되며 전송되지 않습니다.

| 데이터 | 저장 위치 |
|---|---|
| 원격 측정 샘플(신호, 지연 시간, 처리량, 가동률) | 사용자 데이터 디렉터리의 `telemetry.db` (SQLite) |
| 알림과 그 생명 주기 | 사용자 데이터 디렉터리의 `alerts.db` (SQLite) |
| 설정, 프로브 노드, 알림 설정 | 사용자 데이터 디렉터리의 평범한 JSON 파일 |
| 알림 자격 증명(Telegram 봇 토큰, webhook URL, 이메일 비밀번호) | 같은 로컬 JSON 파일 |

서버는 계정, 알림 자격 증명, 파일 경로, 호스트 이름을 **전달받지 않습니다**.

## 2. 두 개의 외부 통신

### 2.1 업데이트 확인 — 자동, 최소한의 데이터

새 버전이 있는지 알려 주기 위해 앱은 `cloud.dishywarden.com`의 업데이트
매니페스트에 접속하고 결과를 보고합니다.

**전송되는 것:** 익명 `client_id`(이 컴퓨터에서 만든 무작위 UUID v4),
앱 버전, 플랫폼, 그리고 요청이 들어온 IP 주소.

**전송되지 않는 것:** 1절에 나열한 모든 항목.

**보관 기간:** 업데이트 이벤트는 90일 뒤 삭제됩니다. 접근 로그는 14일로 회전됩니다.

**끄는 방법:** *설정 → 업데이트 및 피드백* 에서 업데이트 피드 URL을 비우거나,
클라우드 엔드포인트를 지우세요. 그러면 앱은 클라우드에 전혀 접속하지 않습니다.

### 2.2 오탐 신고 — 기본값 꺼짐, 사용자 동의 필요

알림을 오탐으로 표시하면 앱은 경보 규칙을 다듬기 위해 익명 보고서를 보낼 수
있습니다. **이 기능은 기본적으로 꺼져 있습니다.**

**전송되는 것:** 알림 종류, 등급, 제목, 입력한 메모, 앱 버전, 플랫폼,
익명 `client_id`, IP 주소, 그리고 — 설정에 위치 정보가 남아 있는 경우에만 —
좌표.

**전송되지 않는 것:** 계정, 알림 자격 증명, 파일 경로, 호스트 이름,
그 밖의 어떤 원격 측정 데이터도 포함되지 않습니다.

**보관 기간:** 피드백은 90일 뒤 삭제됩니다.

**끄는 방법:** *설정 → 업데이트 및 피드백 → 오탐 샘플 신고* 를 꺼진 채로 두세요.
첫 전송 시에는 어떤 항목이 전송되는지 보여주고 명시적인 동의를 받습니다.
클라우드 엔드포인트를 지우면 외부 요청을 모두 멈출 수 있습니다.

## 3. 익명 처리 방식

- `client_id` 는 이 컴퓨터에서 생성한 무작위 UUID v4입니다.
  하드웨어 식별자, 계정, 네트워크 식별자에서 파생되지 않으며,
  서버가 이 값으로 사용자를 특정할 수 없습니다.
- 필드 화이트리스트는 **클라이언트와 서버 양쪽에서** 강제됩니다.
  목록에 없는 필드는 요청하더라도 버려집니다.
- 클라우드 엔드포인트는 IP 주소별 요청 속도를 제한합니다.

## 4. 데이터 처리 위치

클라우드 서비스는 일본에 위치한 프로젝트 메인테이너가 운영하는 단일 서버에서
동작합니다. 위의 데이터를 UTC 날짜별로 나누어 추가 기록 방식의 JSON 파일로
보관합니다.

## 5. Do Not Track / 쿠키

DishyWarden는 데스크톱 애플리케이션입니다. 쿠키를 설정하지 않고, 트래커를
동작시키지 않으며, 분석 스크립트를 포함하지 않고, 제3자 서비스가 데이터를
받는 일도 없습니다.

## 6. 사용자의 권리

데이터는 익명이거나 자발적으로 제출된 것이고 짧은 주기로 삭제되므로,
다음과 같은 방법으로 권리를 행사할 수 있습니다.

- 2절의 통신을 끄기
- 설정에서 클라우드 엔드포인트를 지우기
- 메인테이너에게 특정 `client_id` 의 데이터 삭제를 요청하기

삭제 요청은 저장소에 issue를 열거나 메인테이너에게 직접 연락해 주세요.

## 7. 정책 변경

중대한 변경은 해당 변경을 포함한 버전의 릴리스 노트에 알리고,
위의 "최종 수정" 날짜를 갱신합니다.

## 8. 문의

개인정보 관련 문의는 저장소의 issue 또는 메인테이너에게 직접 전달해 주세요.
